# 「향 반응 실험장」 아키텍처

기획은 `기획서.md`, 할 일은 `작업지시서.md`. 이 문서는 **코드를 어떻게 나누고, 모듈끼리 무엇으로 대화하는지**를 정한다.
GPT와 Gemini가 동시에 작업해도 충돌하지 않도록, 모듈마다 **담당 파일**과 **공개 인터페이스**를 고정한다.

## 1. 원칙
1. **공용 계약은 `src/exhibit/core/`에만** 있다. `types.ts`(자료형), `events.ts`(이벤트 버스), `tuning.ts`(수치). 다른 모듈은 서로의 내부를 import하지 않고, 계약과 이벤트로만 대화한다.
2. **한 프레임 루프** 하나(`core/loop.ts`). 각 시스템은 `System` 인터페이스(`update(dt, t)`)를 구현해 정해진 순서로 등록된다.
3. **순수 로직과 그리기를 나눈다.** 반응 판정(`play/reactions.ts`), 스토리 진행 판정(`story/goals.ts`)은 three.js 없이 순수 함수 → vitest로 검사.
4. **수치는 `core/tuning.ts`에만.** 반경·수명·속도를 코드 곳곳에 하드코딩하지 않는다(밸런스 조정이 한 파일에서 끝나게).
5. **본편 코드는 가져다 쓰기만**: `src/three/post.ts`(`InkRenderer`), `src/audio.ts`(`sfx`, `setMusic`), `src/ui/dom.ts`. 본편 파일은 고치지 않는다.
6. 외부 네트워크 금지, 에셋은 `src/exhibit/art/`에서 import.

## 3. 프레임 순서 (`loop.ts`가 이 순서로 update)
1. `input` → 2. `player` → 3. `projectiles`(충돌 시 `burst` 발행) → 4. `clouds`(수명·입자, 새 구름 생성 시 `reactions.resolve` 호출 → `reaction` 발행) → 5. `reactionFx` → 6. `paint`(uniform 갱신) → 7. `sniff` → 8. `story` → 9. `hud` → 10. `renderer.render()`
- 일시정지(`paused`)면 1·9·10만.

## 4. 이벤트 (core/events.ts의 `GameEvents`)
| 이벤트 | 보내는 곳 | 받는 곳 | 내용 |
|---|---|---|---|
| `throw` | projectiles | hud, 소리 | 도구, 위치 |
| `burst` | projectiles | clouds | 도구, 위치 |
| `cloudSpawned` | clouds | paint, sniff | CloudState |
| `reaction` | clouds | reactionFx, paint, story, hud | ReactionEvent |
| `pickup` | story/props | tools(인벤토리), hud | 도구 |
| `roomSolved` | story | world(문), hud, paint | 방 id |
| `mode` | main | 모두 | 'title'·'story'·'free'·'paused'·'ending' |
| `sniff` | sniff | hud | SniffView(매 프레임 아님, 바뀔 때) |
| `reset` | main | 모두 | 자유 실험 R 키 |

## 5. 핵심 흐름 예시: 귤 캔 → 민트 캔
1. 클릭 → `projectiles`가 `throw` 발행, 투척체 생성.
2. 바닥 충돌 → `burst{tool:'orange', pos}`.
3. `clouds`가 새 구름을 만들기 전에 반경이 겹치는 기존 구름을 찾아 `resolve(existing.kind, 'orange', ctx)` 호출. 없으면 그냥 구름 생성(`cloudSpawned`) → `paint.add({..., life: cloud.life})`.
4. 민트 캔이 그 구름 안에서 터짐 → `resolve('orange','mint')` = `{ id:'fizzBurst', radius:5, permanent:true }` → 두 구름을 반응 구름으로 교체, `reaction` 발행.
5. `reactionFx`가 섬광·거품 고리, `paint`가 영구 색 구 추가, `story`가 "이 방의 목표 반응인가?" 검사(`goals.ts`), `hud`가 배너.

## 6. 성능 예산 (내장 그래픽, 1366×768)
- 그리기 호출 150 이하: 맵은 같은 재질끼리 합치기(`mergeGeometries`) 또는 InstancedMesh.
- 연기 입자: 구름 24 × 입자 48 = 1152개를 **InstancedMesh 1개**로.
- 색 구 uniform 최대 64. 그림자 없음. 화소 밀도 `min(devicePixelRatio, 1.5)`, `?lowgpu`면 1.
- 30fps 아래로 2초 떨어지면 화소 밀도 자동 0.75배(본편 `stage.ts`의 `adaptResolution` 참고).

## 7. 작업 순서와 병렬 가능 여부
```
T1 빌드 ──────────────────────────────────────────────┐ (아무 때나, 독립)
T2 [A] 맵·이동·루프 ─┬─ T3 [B] 색 셰이더 ─┐            │
                     ├─ T4 [C] 투척·연기 ─┼─ T6 [D] 냄새 ─ T7 [D] 스토리 ─ T8 자유 ─ T10 제출
T5 [C] 반응(순수) ───┘(먼저 해도 됨)      └─ T5b 반응 연출 ┘
T9 모델 연결 [B·C] (T4 뒤)
```
- **동시에 시작 가능**: T1, T2, T5(순수 반응표+테스트).
- T2가 머지되면 T3·T4·T6(HUD 껍데기)를 동시에.
- T3·T4가 머지되면 T5b(반응 연출)·T6(킁킁)·T7.
